Bronze · o dado como veio

O mesmo comando lê Excel, JSON e XML

-- as 20 planilhas de uma vez: é só apontar a pasta
FROM read_files('.../raw/excel/',
  format => 'excel', headerRows => 1,
  inferColumnTypes => false)

-- cada arquivo do ClickUp é uma lista com tarefas dentro
SELECT list.name, explode(tasks) AS t
FROM read_files('.../raw/clickup/',
  format => 'json', multiLine => true)

-- cada <Task> do Project vira uma linha
FROM read_files('.../raw/msproject/',
  format => 'xml', rowTag => 'Task')
Nada de conversão antes
Ninguém exportou CSV, ninguém abriu planilha. O arquivo que o gerente salvou é o arquivo que entra.
A regra da bronze
CSV e Excel entram como texto: se o Databricks adivinhasse o tipo, a data em dois formatos e a vírgula decimal sumiriam antes de você ver. JSON e XML mantêm a estrutura.

Exemplo 05 · como gestão de projetos mede atraso

Dois números contam se o projeto está no prazo

Planejado
horas que deviam estar prontas até hoje, pela baseline
Agregado
horas que estão prontas: horas da tarefa × % concluído
SPI = agregado ÷ planejado
0,80 = o projeto andou 80% do que devia. Abaixo de 1 é atraso.
CPI = EV ÷ custo real
0,80 = cada R$ 1 gasto entregou R$ 0,80. Abaixo de 1 é estouro.

"Hoje" é sempre DATE'2026-10-16', nunca current_date(). Corte da Torre: abaixo de 0,9 = atenção, abaixo de 0,8 = crítico.
